# 模型资源导入约定

2026-10-08 用户明确要求：许可不明确的资源也导入，按作者归档，并标记好来源与许可状态，方便后续作者署名和追溯。本约定替代此前因许可缺失或不明确而不导入的默认做法。

## 作者归档与来源

- 模型放入 `public/resources/Model/GLB/artist_作者名称/`。
- 共享贴图放入 `public/resources/Model/SharedTextures/artist_作者名称/`。
- 同一作者下可按套件分类；去重保留别名和原始文件映射，作者目录不能代替具体模型的来源记录。
- 在作者目录的 `NOTICE.md`、`LICENSE-SOURCES.json` 和导入清单中保存作者、套件、模型对应关系、原始本地路径、已取得的来源链接及署名文字。原许可文本保存在 `SourceNotices/`；没有找到文本时明确写“未找到许可文本”，不创建虚构的作者许可。
- 不同套件许可不同时逐套件记录，不把整个作者目录统一标成同一种许可。找不到链接或作者要求的署名文字时标记缺失，不猜测。

## 许可不明确时继续导入

许可缺失、不明确或证据冲突不阻止导入，也不需要仅为这项不确定性再次向用户确认。在展示预设和依赖清单中正常引用这些模型，并保留如下状态：

```json
{
  "licenseStatus": "unverified",
  "commercialUseVerified": null,
  "importDecision": "included_by_user_request",
  "licenseNote": "许可未核实；按用户2026-10-08要求导入，保留作者和来源以供署名及追溯。"
}
```

`licenseStatus` 可使用 `verified`（有明确证据）、`unverified`（缺失或不明确）、`conflicting`（证据冲突）和 `restricted`（原文有明确限制）。记录找到的证据、核查日期及明确限制；用户的导入决定与作者的授权证据分别记录，不把未知改写成已获商业许可或 CC0。

后续找到许可后更新对应套件和模型的记录，保留旧状态及证据出处。已有明确许可的记录不因本约定改变。此前用户明确要求删除、且许可明确限制商业使用的资源，不因这次针对“许可不明确”的要求自动重新导入。

## 其他导入要求

继续采用项目现有的 glTF 2.0 GLB、按作者共享贴图、去重和展示预设流程。贴图尺寸遵循用户对当批资源的要求；当前默认上限为512×512，小图不放大。保留原始来源，不将转换中间文件发布为运行时资源。
