# Grid 战斗逻辑工作台

React Grid Layout 2.3.0 已安装。开发服务运行时打开：

[Clash Grid · 战斗逻辑工作台](http://localhost:1184/labs/draggable/clash-lab/grid.html)

项目首页“可拖拽 Lab”分组和 Puck 运行页也提供入口。没有启动开发服务时，在项目目录运行 `npm run dev`。

## 使用方法

1. **排列面板**：按住面板标题栏拖动位置，从四个角调整宽高。布局设置提供精度、触发距离、补位、碰撞处理和坐标微调；自由叠放允许重叠、不让位，点击窗口置顶。面板内部滚动，拖动输入框不会移动面板。
2. **调整单位**：点击单位窗口顶部的标签切换项目。窗口按单位摘要、名称、技能与骰子、基础参数、特殊状态纵向展开，全部常驻显示。点击标签旁“＋ 新建”创建并选中新单位，“删除”只删除当前标签。重命名后标签文字同步更新；切换标签保留已编辑数据。
3. **调整技能**：单位名称下方就是所属技能的标签页，点击切换当前出战技能，并直接编辑骰子与效果。新建后立即选中；切换单位同步显示其技能，运行数据同步更新。
4. **执行测试**：顶部“开启拼点”和“回合结束”调用原有战斗管线；“清空日志”只清理日志。无须进入预览模式。
5. **检查运行数据**：勾选“运行数据”，查看当前双方单位、技能、状态和选中 ID 的 JSON。
6. **锁定与显隐**：点击“锁定布局”固定位置和大小，业务控件仍可操作。取消顶部面板勾选或点击面板右上角 × 可隐藏面板，再次勾选恢复；隐藏不会删除战斗数据。

## 保存与恢复

- 拖动、缩放、显隐和锁定后，布局自动保存到当前浏览器。保存状态显示在面板选择栏下方。
- “导出布局”下载面板位置、大小、显隐和锁定配置；“导入布局”校验并立即使用。格式错误时保留当前布局。
- “恢复默认布局”恢复初始面板安排并保存，**不会重置当前战斗数据或日志**。
- 仅布局持久化。刷新或跳转页面后，战斗数据仍恢复成示例；浏览器、主机名、端口不同会使用不同的本地存储。
- 保存键为 `clash-lab.grid-layout.v1`，与 Puck 布局独立，两个工具的 JSON 不通用。
- 窄屏（容器宽度小于 900px）按单列展示，暂停拖动和缩放；放宽窗口恢复原桌面布局。窄屏排列不会覆盖桌面布局。

Grid 工作台适合调整功能面板、持续运行逻辑测试；Puck 适合组装和编辑更细粒度的界面组件。两者复用 `shared/CombatWidgets.tsx` 与同一套战斗状态/API，战斗规则保持不变。当前管线每次拼点自身包含回合结束钩子，顶部“回合结束”还会额外结算并推进计数。

## XP 工业控制台外观

工作台使用紧凑的 XP 蓝色标题栏、灰米色控制面板、凹陷输入框、表格参数和实时底部状态栏。默认四个窗口：左右单位窗口内直接包含技能与骰子，右列上下展示战斗日志和运行数据。旧六窗口布局读取或导入时，将各侧技能窗口的高度合并到对应单位窗口，保留其余位置、显隐和锁定设置。点击“恢复默认布局”采用新版四窗口排列。内容按紧凑尺寸展示，剩余桌面区域保留。

单位与技能使用 XP 标签页管理。删除当前项后优先选择其右侧相邻项，没有右侧项则选择左侧项；删到最后一个显示空态，仍可新建。标签过多时横向滚动；焦点位于标签上时可用左右方向键切换，Home/End 跳到首尾。Grid、Puck 和完整参数页采用同一交互，Puck 设计模式仍禁用业务操作。状态类型和效果类型属于属性枚举，继续使用下拉框。

开发入口：`gridLabMain.tsx`。工作台配置：`grid/GridWorkspace.tsx`。布局与校验：`grid/gridLayoutData.ts`。拖拽、设置和保存共用 `labs/kit/draggable/GridWorkbench.tsx`。新增面板时同步标题、默认几何、内容分发、校验和测试。

验证：`npm run typecheck:clash`、`npm run test:clash`、`npm run test:lab-entries`。

官方文档：[React Grid Layout](https://github.com/react-grid-layout/react-grid-layout)。
