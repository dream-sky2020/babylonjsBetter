# Press Turn · 大小行动点战斗 Lab

独立于 Clash Lab 的行动点制战斗原型。沿用紧凑 XP 工控台外观，拥有自己的类型、示例、Zustand store、纯函数结算引擎及布局存储，不导入 Clash 战斗代码。

## 三个入口

- `index.html`：Puck 运行页，读取本 Lab 已保存的 Puck 布局。
- `editor.html`：Puck 编辑器，可拖入绑定我方或敌方的角色数据编辑器、操控面板、行动点、指令、重开控制、日志、规则、JSON、多列和 XP 窗口组件；设计模式禁用业务操作，“交互预览”允许执行战斗。
- `grid.html`：React Grid Layout 工作台，面板可拖动、缩放、显隐、锁定，使用页面全部宽度；小于 900px 单列展示，不覆盖桌面布局。

项目首页普通 Lab 分组提供三个入口。运行 `npm run dev` 后访问 `http://localhost:1184/labs/standalone/press-turn-lab/grid.html`。

## 操作

1. “我方角色数据”和“敌方角色数据”分别编辑对应队伍，单位与技能用标签切换。名称、HP/MP、攻击/防御、技能威力/属性/命中/暴击/MP 消耗/范围、八类属性相性均可编辑。新建和删除只操作所属队伍；编辑对象选择不改变当前行动者和战斗目标。
2. “操控面板”随阶段操控我方或敌方，顶部标明当前操控方。显示当前行动者的基础面板，选择技能、点击目标后显示目标的基础面板（HP/MP、攻防、相性）。执行后实时跟随新的行动者；选中目标倒下或被删除时自动回退到有效目标。治疗选择己方目标，全体技能作用于全部存活目标，仍可点击成员查看基础面板。
3. “行动点与指令”保留行动点/阶段、掷判模式、结束阶段和行动者调试切换；可跳到当前方任意存活成员。实际执行技能、防御、让过在“操控面板”操作。伤害、治疗、阶段和行动点消耗记录均在独立的“结算日志”面板显示。
4. 普通执行按命中率/暴击率随机；必定命中不暴击、强制暴击、强制未命中用于复现规则。示例先锋火炎命中冰霜守卫：220 → 156 HP，3大/0半 → 2大/1半，轮到术士。
5. 防御减半承伤，到本方下一阶段开始时解除。让过保留半行动点。耗尽行动点自动换手；也可主动结束阶段。双方均可手动或点击“自动选择并执行一次行动”，每次点击只执行当前行动者的一步，不会持续自动战斗。
6. “按当前配置重开”保留编辑后的队伍/技能/相性，恢复所有 HP/MP，并按当前我方人数开始新战斗。“恢复示例”重新创建初始队伍。新增/删除成员不会中途增减本阶段点数；重开或换手时重新计算。

## 自动一步

`autoAction.ts` 以当前阶段和行动者选择一个行动，自动选技能和目标后调用同一结算引擎，沿用“掷判模式”。仅考虑 MP 足够的技能与存活目标，避免无效/反射/吸收；全体攻击有任一无效类目标时跳过。评分考虑有效伤害、弱点、击杀和治疗收益，对低于半血队友的治疗增加优先权。没有安全可用技能时让过。日志记录选择理由。选择策略不改伤害和行动点规则，不启动计时器或自动循环。

## 已确认的首版规则

本实现以用户确认的规则为准，作为《暗喻幻想》/《女神转生》风格的可测试原型，不宣称完整复刻任何一作。

| 行动结果 | 行动点 |
| --- | --- |
| 普通命中、耐性、治疗、防御 | 优先移除一个半点，否则移除一个大点 |
| 弱点、暴击、让过 | 一个大点变为半点；没有大点时移除一个半点 |
| 未命中 | 移除两个图标，半点优先；不足两个则耗尽 |
| 无效、反射、吸收 | 清空本方剩余图标 |

弱点与暴击同时出现只奖励一次。全体攻击对每个目标分别计算伤害，整次行动只结算一次图标，优先级为无效类 > 未命中 > 弱点/暴击 > 普通。换手时按下一方存活成员数补充大点，从首名存活者开始按队伍顺序轮流行动。敌方阶段结束后回合数加一。全灭立即结束，不补充下一方点数。

基础伤害 `max(1, 威力 + 攻击 - 防御)`；弱点和暴击分别 ×1.5，耐性和防御姿态分别 ×0.5，结果向下取整且至少为1。万能忽略相性。反射对行动者造成一次伤害，不递归反射；吸收恢复目标 HP，上限为 maxHp。技能支付一次 MP，未命中/无效仍支付；MP不足、无效行动者或目标被拒绝，不扣资源。治疗不复活、不触发弱点/暴击。

首版尚未加入 Archetype、合题/协同技能、召唤、Buff/Debuff、异常状态或持续自动战斗。

## 代码位置

| 文件 | 职责 |
| --- | --- |
| `types.ts` | Unit / Skill / Battle / Icons / Action，属性与相性枚举 |
| `data.ts` | 初始 3 对 3 队伍，新建单位/技能默认值 |
| `engine.ts` | 行动点消耗、伤害/治疗/相性、顺序、换手、胜负、重开；不依赖 UI 或 store |
| `store.ts` | 会话状态及编辑动作，调用纯函数引擎 |
| `playerContext.ts` | 统一推导当前行动者、技能、有效目标及战斗结束状态 |
| `autoAction.ts` | 双方通用的单步行动选择与理由，独立于伤害结算 |
| `widgets.tsx` | 两方角色编辑、操控面板与基础卡片、行动点、指令调试、独立日志和规则组件 |
| `layouts.ts` | Grid/Puck 默认布局、导入校验、独立存储键 |
| `GridWorkspace.tsx` | Grid 拖动、缩放、显隐、锁定、导入导出 |
| `puckConfig.tsx` / `PuckWorkspace.tsx` | Puck 组件注册、运行与编辑页 |
| `style.css` | 本 Lab 独立的 XP 工控台样式 |

布局键 `press-turn-lab.grid.v1` 和 `press-turn-lab.puck.v1` 独立于 Clash，两种 JSON 也不能互换。Grid 格式现为 `press-turn-grid-v3`，包含七个面板，默认四列。旧 v1/v2 布局保留已有几何/显隐/锁定并补齐双方编辑与操控面板；旧 Puck 合并编辑器拆为我方/敌方窗口，操控窗口改名，指令窗口中嵌入的日志拆成独立窗口。已有自定义布局可点击“默认布局”采用新的四列排列。

仅布局保存在当前浏览器；战斗数据、编辑内容、日志、目标和掷判模式不持久化，刷新或切换入口恢复示例。目标和掷判模式在当前页面 store 中共享，因此多个玩家操控组件也保持一致。每个页面的战斗会话独立。

检查：`npm run typecheck:press-turn`、`npm run test:press-turn`、`npm run test:lab-entries`。
