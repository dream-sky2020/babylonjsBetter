# Dungeon Agent 追踪与 Debug

地牢地图编辑器中选择 Agent 的「行动控制器」组件：控制器为 `chase-player` 时，「追踪寻路策略」可选完整路径规划（`path`）、直接靠近（`direct`）、靠近并沿墙绕行（`wall-follow`）。策略存储在 `parameters.navigationStrategy`；旧地图未配置时使用 `path`。组件中的 Debug 颜色可填写 `#RRGGBB`，留空使用自动颜色。保存地图后配置随地图生效。

组合式 Dungeon Agent Lab 的「可移动 Dungeon Agent」面板可选择 Agent，临时切换 Controller 参数中的寻路策略，或用颜色选择器临时覆盖 Debug 颜色。恢复颜色按钮撤销运行时颜色覆盖；恢复 Controller 按钮恢复地图中的行为配置。两种运行时覆盖不会写回地图，切换地图后清除。未手动指定颜色的追踪者按策略显示：直接靠近绿色 `#22c55e`、沿墙蓝色 `#38bdf8`、完整路径红色 `#ef4444`；其他 Controller 沿用阵营颜色。

直接靠近只考虑能缩短距离的合法单步；沿墙策略按格子通行结果固定绕行方向，并记录进入绕行的格子、朝向和历史。离开绕行前检查后续可通行方向；玩家换格不会清空绕行历史。遇到动态占位时优先尝试其他合法方向，局部路线被临时占用时等待。检测到绕圈或达到 32 步后，在最多 8 步、展开最多 64 个格子的范围内搜索出口，并与其他 Agent 共享每次决策的搜索预算；无出口时冷却重试。追踪 Controller 的「绕行失败后回退完整寻路」可选开启，默认关闭；地图配置使用 `parameters.wallFallbackToPath: true`。轻量策略不保证能在复杂迷宫中抵达目标；斜向的停止距离按最少格步计算。所有实际移动仍由空间通行和动作仲裁决定。完整路径在规则拓扑使用 A* 启发式，非局部拓扑回退到原搜索；预约代价和阻挡规则保持生效。

广场预设 `dungeon_map_2` 将普通追踪者设为沿墙策略，整格追踪者保留完整路径；长廊预设 `dungeon_map` 的普通追踪者使用直接靠近。也可在面板临时切换策略以对比。Agent 面板显示当前 Agent 的决策次数、平均及最长同步耗时、搜索次数及访问格数，搜索统计包括局部绕行与完整搜索；切换策略后可清空统计再比较。寻路耗时已包含在决策耗时内，不应相加。使用「系统诊断 → Lab 性能统计」采集帧耗时和模块耗时；该面板仍不能独立拆分碰撞耗时。
