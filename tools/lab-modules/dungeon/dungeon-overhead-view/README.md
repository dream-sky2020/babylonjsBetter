# Dungeon Overhead View

在组合式 Lab 的 `modules` 中加入 `dungeon-overhead-view` 即启用可选协调器。依赖由 catalog 自动装配：玩家移动、玩家相机、格子 Debug、障碍 Debug 和地图加载器。未加入此模块的 Lab 保持原行为。

正式使用：在地图编辑器的地图容器内创建“俯视显示配置”实体，其默认专用组件保存设计角度、投影与比例策略。沿地图编辑器原有保存路径写入地图。不增加独立配置文件或浏览器存储。

临时试验：在统一配置面板编辑参数后点“应用测试草稿”；草稿优先于地图声明。LabState 的 `dungeon-overhead-view/settings` v1 保存 `{ enabled, draft }`。恢复地图配置会清除草稿；没有地图组件则释放控制、回到原布局。普通模块默认没有草稿。测试 Lab 显式传入自己的 45° 草稿。

控制方向：地图组件 / 测试草稿 → 纯计算 → 四个消费者服务的独占句柄。角度不会被滚轮或自由相机的变化改写；外部控制生效时玩家相机面板隐藏重复设置，并标明统一配置来源。正交范围仍通过公共控制器生效，透视 FOV 保留。

协调器首次接管时进入俯视，记录之前的玩家模式。V 切换到第一人称或关闭玩家绑定会暂停映射；返回俯视重新应用。关闭协调、移除声明或卸载会释放全部句柄、恢复原玩家模式；切图重新使用新地图的 mapOffset/tileSize，无配置时不保留前图变换。模块注销地图/相机订阅和 LabState 引用，不创建帧观察者或输入监听。

仅显示层参与：玩家标记、格子 Debug、障碍及预约 Debug 和相机目标。实际 Runtime 位置、朝向、移动进度/耗时、碰撞和场景美术不缩放。以后场景美术接入应由自己的表现模块提供同样的消费者接口，不能修改逻辑坐标解决显示问题。

自动补偿仅支持正向正交俯视（15–89.99°，yaw 0° / ±180°）；等距斜向支持原比例或手动倍率。第一人称不支持正交；玩家模块未新增侧视和无人机模式。公共相机的既有模式不受影响。
