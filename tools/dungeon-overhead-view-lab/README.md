# 俯视比例测试 Lab

启动项目开发服务后访问 `/tools/dungeon-overhead-view-lab/index.html`，或从首页选择 Dungeon Overhead View Lab。

1. 默认加载原有地图，使用独立 45° 正交草稿；格子与障碍 Debug 自动显示。
2. 在“俯视显示 · 统一配置”面板把俯视角改成 30°，点击应用。等宽深格子的 Z 显示倍率应为 2，地面投影仍为方格。
3. 调整正交垂直半范围，改变窗口宽高，确认方格比例不变。
4. 玩家移动中切换角度；V 切第一人称后回到原布局与透视 FOV，再按 V 恢复补偿。
5. 关闭协调或点击恢复地图配置，比较原布局；无对应地图组件时没有缩放。修改草稿不会写入地图，可通过 Lab Snapshot 导出/恢复。

此 Lab 还组合 `dungeon-visual-deformation`，在出生点附近放置两个共用 PBR 材质的方柱（完整强度和半强度）、Standard 材质骨骼摆动模型，以及 2D Shader 精灵。原地图不被写入；已有场景美术布局仍保持原状。若关闭了玩家相机绑定，请重新开启再测试俯视。

示例补光灯只照这四个示例 Mesh，不影响地图地面、原有模型或切图后新建的场景对象；真实渲染验证会比较 Standard/PBR 场景对象在补光开关前后的像素颜色。

在“显示变形 · 批量控制”面板测试：

1. 默认仅作用于 `sample-models` 和 `sample-sprites` 分组。对象规则 `sample:half` 把第二个方柱强度覆盖为 0.5。
2. 修改统一俯视角并应用，观察物体脚底固定、上部随俯角补偿。参考俯角 0° 表示保留正面竖直高度；不会再次缩放地面格子。
3. 将第二个方柱对象强度设为 0，验证共享材质没有让它跟随其他对象变化。选择“全部已接入对象”可包含场景模型和几何，具体支持状态见对象列表。
4. 改用手动倾斜，尝试 -1、0、1 及高度倍率；每次点击应用。V 切换到第一人称会恢复原形，回到俯视恢复设置。
5. 导出快照、修改、恢复快照；“恢复地图变形配置”清除草稿，地图无组件时应全部恢复。切图和卸载后不残留矩阵、拾取及深度覆盖。

自动验证：`npm run test:dungeon-overhead-view`、`npm run test:deformation`；启动开发服务后可运行真实渲染验证 `npm run test:deformation-webgl`。生产入口构建：`npm run build:camera-labs`。
